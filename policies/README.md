# 保障强度不是一个模糊滑块

用户界面可以只显示三项：`快速探索`、`平衡取证`、`严格门禁`。运行时必须把选择冻结为完整的 `AssuranceRunPolicy`，因为检查范围、证据深度、Provider 预算和结论权限是不同维度，不能只保存一个“强度=70%”。

- `快速探索 / EXPLORE`：允许单 Provider 和较小预算，输出线索与局限，最终结论只能是 `NO_VERDICT`。
- `平衡取证 / EVIDENCE`：按风险触发交叉验证，输出证据报告；仍不能签发 `ACCEPT`。
- `严格门禁 / ENFORCE`：使用阻断式 Gate，只有完整 RunBundle 通过结构和语义校验后才可能签发最终 Verdict。

高级用户可以以任一预设为基线修改独立策略轴；一旦修改，运行记录必须使用 `CUSTOM`，绑定基线 Policy 的内容摘要，并由系统重新计算 `outcome_authority` 和 `allowed_final_verdicts`。任何降低覆盖、鲜度、Canary 或交叉验证要求的改动，都不能保留更高的结论权限。

所有档位始终执行五项不可关闭的不变量：不得编造、不得隐藏冲突、用户错误是一等证据、不得越权修改、不得过度声称。用户选择的是“检查多少和等多久”，不是“是否允许说假话”。

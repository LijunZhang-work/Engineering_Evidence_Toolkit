# 独立能力目录

状态：`DESIGNED`（本目录是设计规范，不代表任何能力已经实现或验证）。

本目录中的每个子目录都是一个可以单独调用、单独替换、单独测试的能力。能力只产出事实、证据或分析结果；是否把结果映射为门禁、是否要求修复、是否允许交付，由上层 profile 决定。任何能力都不得因为被某个 review profile 使用，就依赖该 profile 才能运行。

## 共同约束

- 独立入口：调用方只需提供该能力声明的输入，不必启动完整 Review。
- 证据优先：结论必须指向可定位的证据；缺证据输出 `UNKNOWN`、`NOT_QUALIFIED` 或受限结论，禁止猜测。
- 失败关闭：工具未安装、环境不合格、覆盖不完整或解析失败时，不得把“没有检出”写成“没有问题”。
- 状态分离：任务状态、执行状态、证据资格、事实结论和 profile 门禁互不混用。
- 默认无业务修改：除非能力规格明确声明，否则只允许写入独立的运行产物目录，不得修改仓库、依赖、系统配置或用户文件。
- 可追溯：输出须记录输入快照、工具/规则版本、时间、覆盖范围、失败项和证据位置。
- 可组合：能力之间只通过公开输入/输出契约连接，禁止读取其他能力的私有临时文件。
- 环境策略外置：能力只声明访问需求；公司网络、模型 API、密钥、外发、下载和制品来源由唯一的外层运行边界裁决。

## 独立调用最小规则

1. 读取目标能力的 `CAPABILITY.yaml` 和 `SPEC.md`。
2. 创建唯一 `run_id`，固化输入快照，不复用无来源的旧结论。
3. 先执行资格检查和负向 canary，再执行主体检查。
4. 保存输出、失败与证据，不把 `UNKNOWN` 美化为 `PASS`。
5. 只有 profile 可以把能力结果解释为放行、阻断或修复要求。

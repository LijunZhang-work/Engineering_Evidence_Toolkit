# Evidence Kernel

状态：`DESIGNED`。

## 职责

把不同工具、人工材料和其他能力的原始观察，规范化为可追溯的 `claim + observation + receipt + provenance + limitation` 证据包。它负责证据身份、去重、冲突并存、覆盖范围和结论天花板，不负责决定业务是否正确。

## 非职责

- 不搜索代码、不执行编译、不修改代码。
- 不替 profile 作 PASS/FAIL 门禁裁决。
- 不因为多条低质量证据一致，就把它提升成高权威事实。
- 不把工具成功退出等同于检查成功，也不把“未检出”改写成“不存在”。

## 独立入口

`normalize_evidence(run_context, raw_observations, claims?, receipts?) -> evidence_bundle`

适用于临时搜索、代码审查、事故复盘或完整 Review；调用者无需启动其他能力。

## 输入与输出

输入至少包含 `run_id`、工作区/资料快照引用、原始观察、产生观察的方法及覆盖范围。输出必须为每个声明记录：唯一 ID、精确措辞、支持/反驳证据、来源位置、推导方式、权威等级、时效、覆盖、限制和状态。

推导方式、断言来源、权威等级必须分列，禁止混成单一“证据等级”。冲突证据必须同时保留并显式标记，不能以最后写入者覆盖。

## 失败关闭

输入缺少来源、工具版本、快照或覆盖信息时，相关结论只能为 `NOT_QUALIFIED` 或 `UNKNOWN`。解析失败必须生成失败收据；禁止丢弃失败项后输出全绿。

## Side effects

只允许写入当前 run 的证据包和索引；不得触碰仓库、系统配置、第三方服务或既有账本。

## 验收要点

- 同一输入重复规范化得到稳定 ID 和等价语义。
- 支持证据与反证可同时存在，不互相吞掉。
- 缺少 provenance 的 canary 不能得到 `SUPPORTED`。
- 输出可由机器校验，也能从证据位置回到原始材料。

# Report Renderer

状态：`DESIGNED`。

## 职责

从同一份事实、证据和 profile 决定生成两种同步视图：专业版保留方法、范围、target、证据、失败与限制；小白版用清楚语言说明“发现了什么、影响什么、什么没检查、下一步是什么”。两版语义必须一致。

## 非职责

- 不重新运行检查，不替代证据内核。
- 不为了好看隐藏失败、未知、未覆盖、外部反证或停机原因。
- 不在小白版把 `UNKNOWN` 翻译成“应该没事”。
- 不自行生成 PASS/FAIL；只呈现 profile 已给出的决定。

## 独立入口

`render_report_views(evidence_bundle, reporting_scope, profile_decisions?) -> report_package`

## 输入与输出

两个视图必须共享稳定 finding/claim ID。专业版包含输入快照、工具/环境资格、检查矩阵、反证、未决和证据索引；小白版逐项链接相同 ID，并明确区分“已证实问题”“合格范围未检出”“没有资格检查”“等待外部组件”。机器摘要用于一致性校验，不是第三套事实。

## 失败关闭

证据包冲突、关键产物缺失、两版状态不一致或 profile 决定无来源时输出 `INCONSISTENT/NOT_QUALIFIED`，不得发布完整报告。报告生成成功不代表工程检查成功。

## Side effects

只写报告文件和索引；不得修改证据包、账本、代码或发送报告。

## 验收要点

- 同一 ID 在两版的严重度和状态完全一致。
- Windows 无 DT 的证据天花板在小白版仍清楚可见。
- 用户提供的错误不会在摘要中消失。
- 报告可从任一关键结论跳回原始证据。

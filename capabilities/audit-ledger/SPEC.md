# Audit Ledger

状态：`DESIGNED`。

## 职责

为每次能力调用、代码修改、验证、结论修正、人工输入和停机决定写入追加式事件，形成可排序、可校验、可回溯的执行轨迹。它防止失败、撤回和未知项在最终报告中消失。

## 非职责

- 不判断事件内容真假或质量。
- 不替代原始日志、diff、证据包或版本控制。
- 不允许用后写事件覆盖、删除早期错误结论；只能追加更正。

## 独立入口

`append_audit_event(run_id, event, artifact_refs?) -> ledger_entry`

## 输入与输出

事件至少包含序号、UTC 时间、actor/provider、动作、输入快照、输出摘要、状态、失败/限制、关联任务与产物。条目以稳定哈希引用前项；大产物只存摘要和不可歧义位置。更正事件必须引用被更正条目和理由。

## 失败关闭

序号冲突、前链不匹配、必填 provenance 缺失或账本损坏时拒绝写入并输出 `CORRUPT/REJECTED`。不得在账本不可用时继续宣称全过程可审计。

## Side effects

唯一允许副作用是向指定 run 账本追加条目和索引；禁止覆写旧条目、修改仓库或外发数据。

## 验收要点

- 篡改中间条目会被链校验发现。
- 同一幂等键重复提交得到 `DUPLICATE`，不会生成双事件。
- “本地说没问题”被用户错误反证后以追加更正体现。
- 最终报告中的每个关键状态可追到事件与产物。
